# 1.22.0 (v82) — הרובוט האמיתי של הקבוצה

בעל הקבוצה מעלה באפליקציה את שני הקבצים שפרויקט 02 מייצא (`robot-apollo9662.json` ו־`robot-apollo9662.glb`), וכל מי שהצטרף לקבוצה בקוד מקבל את הרובוט: במוסך מופיעה בנייה חדשה, ״🏆 הרובוט האמיתי שלנו״, עם המודל האמיתי על הזירה וההתנהגות לפי המספרים מהקובץ.

**שום נתון של הרובוט לא נמצא בקוד או במאגר הזה.** הקבצים עוברים רק בין המחשב של הבעלים, הענן של הסימולטור (דלי פרטי) והמחשבים של חברי הקבוצה. כל המספרים נגזרים מהקובץ בזמן הטעינה. הבדיקות משתמשות ברובוט דמיוני (`test/v82_fixture.mjs`).

## מי עושה מה

| מי | מה |
|---|---|
| בעל הקבוצה (`bb_teams.owner`) | הגדרות ← חשבון ← ״⬆ ייבוא הרובוט האמיתי״: בוחרים את שני הקבצים יחד. ״החלף״ לגרסה חדשה, ״מחק״ |
| כל חבר בקבוצה | הרובוט יורד לבד בסנכרון. ״השתמש בו״ בחלונית החשבון, או במוסך |
| מי שלא בקבוצה | לא רואה כלום, גם לא שיש רובוט |
| חשבון חסום | לא קורא ולא כותב |

יציאה מהקבוצה, התנתקות או חשבון אחר — המטמון במחשב נמחק, והבחירה חוזרת לקלאסי.

## בשרת — `supabase/v82_team_robot.sql`

- `bb_team_robot` — שורה לכל קבוצה: גרסה, הג׳ייסון (עד 512 ק״ב), הנתיב של המודל, גודל, מי ומתי. הרשאות ברמת השורה, בלי גישה ישירה לאף תפקיד ציבורי.
- הדלי `team-robots` — פרטי, עד 12 מ״ב, רק `model/gltf-binary`. נתיב: `<team_id>/robot-v<גרסה>.glb`. מדיניות על `storage.objects`: חבר קורא רק את התיקייה של הקבוצה שלו; רק הבעלים כותב, מחליף ומוחק בה.
- `bb_team_robot_get()`, `bb_team_robot_set(ver, data, path, size)` (רק בעלים; הפורמט, הגרסה, הגודל והנתיב נבדקים), `bb_team_robot_clear()` (רק בעלים).
- בלי `service_role`. נבדק על Postgres מקומי עם תחליף לאחסון: `test/sql/v82_team_robot_test.sql` (39 בדיקות), דרך `test/v81_admin_sql_test.sh`.

## באפליקציה — `app/sync.js`, `app/main.js`, `app/preload.js`

- `robotPush` — בדיקת הקבצים (פורמט `apollo9662-robot/1`, גרסה, מידות, glb תקין, גדלים), העלאת המודל, ואז הנתונים. גרסה חדשה מוחקת את הקובץ הישן מהדלי.
- `robotPull` — בכל סנכרון של הקבוצה: מורידים רק כשהגרסה או הזמן בשרת השתנו. נתיב של קבוצה אחרת או מודל פגום — לא נשמרים.
- המטמון: `team-robot/robot.json` + `robot.glb` בתיקיית הנתונים. לא בגיבויים, לא בסנכרון של הנהגים, לא בדיווח באג.
- הדף מקבל את הרובוט רק אם הוא של הקבוצה שהחשבון המחובר חבר בה עכשיו.

## בסימולטור — `biobuzz-sim.html` (המודול ״v82 — הרובוט האמיתי של הקבוצה״)

**מראה:** ברמה מלאה ומאוזנת — המודל האמיתי (glb), עם הצללה שטוחה (בקובץ אין נורמלים), פוליקרבונט שקוף, וחלקים שמסתובבים (גלגלי הנעה, איסוף, העברה, ירי). ברמה מהירה — אותם חלקים כצורות פשוטות מהג׳ייסון, מאוחדות לרשת אחת לכל צבע. הרובוט המצויר נשאר מוסתר בשביל הסמנים (לוע, מצלמה). פס הברית נשאר.

**מה נגזר מהקובץ (בלי בלוק sim):**

| פרמטר | מאיפה |
|---|---|
| רוחב, אורך | תיבה סביב כל החלקים, בלי מערכת ״סוף משחק״ (רמפת הפרח). המודל מוזז כך שיישב באמצע תיבת הפיזיקה |
| מסה | `summary.mass_kg_est` |
| הנעה | `drive.type`, `wheel_d_mm`, `motor_rpm`, `ratio` |
| סוג איסוף | מכאנום אם יש גלגלי מכאנום במערכת האיסוף |
| העברה | רצועה אם יש מערכת טרנספר |
| יורה | הוד אם יש רמפה במערכת הירי |
| קוטר גלגל הירי | הגליל הכי גדול שמסתובב במערכת הירי (בלי גלגלות ומרווחים) |
| גובה האיסוף | הגובה הממוצע של מה שמסתובב במערכת האיסוף |
| מצלמה | החלק במערכת המצלמה שאינו העריסה: מיקום, והזווית לפי הציר הדק שלו |

**הבלוק `sim` (רשות, מבקשים מ־02):** מה שאי אפשר לגזור מהחלקים.

```json
"sim": {
  "exit_mm": [x, y, z],          // נקודת היציאה של מרכז הכדור, בצירים של הרובוט
  "exit_deg": 60,                 // זווית היציאה מעל האופק
  "shooter_ratio": "1:1",         // מנוע הירי לגלגל
  "capacity": 4,                  // כמה כדורים
  "balls": "pollen",              // pollen / both / nectar
  "intake_side": "front",         // front / back / both
  "camera": { "pitch_deg": 25, "fov_v_deg": 50 }
}
```

בלי הבלוק: הלוע, זווית הירי והתמסורת נשארים כמו במעבדה, 4 כדורים, איסוף מקדימה, וכל הכדורים.

**ברשת:** עוברת רק הבנייה (שלדה, איסוף, יורה וכו׳), בלי השם, בלי ההסבר, בלי המודל ובלי המספרים המדויקים.
